# 面试讲稿与高频追问

> 配套 `RESUME.md`。目标：**30 秒讲清是什么，2 分钟讲清难在哪，被追问时每个数字都能落地。**

---

## 一、30 秒版（自我介绍里提到这个项目时）

> 「我做过一个智能旅行规划助手。用户输入目的地、日期和偏好，后端由 **4 个 Agent 协作**——
> 景点、天气、酒店三路**并发**检索，再由一个规划 Agent 合成带**真实坐标、天气和预算**的行程。
> 底层用高德地图的 MCP 拿真实 POI。前端我做了两套等价的：Web 和小程序，
> 共用同一个 FastAPI 后端。后端最后是**打包上微信云托管**，让体验版在真机上真正跑通的。」

**要点**：每个词都是具体的（4 个 Agent / 并发 / 真实坐标 / 云托管 / 真机）。别用「实现了智能规划」这种空话。

## 二、2 分钟版（「详细讲讲这个项目」）

按「**问题 → 动作 → 结果**」三段走，不要按代码目录讲。

1. **起点（10s）**：这个项目起始于《Hello-Agents》教程第 13 章的示例。原版是一条**串行**链路，
   四个 Agent 排队跑，一次请求 **82 秒**，而前端超时是 115 秒——**离超时只差一步**，基本不可用。

2. **最大的改动（40s）**：我把前三个检索型 Agent 改成并发。它们的输入互不依赖，只有第四个
   规划 Agent 需要前面三个的结果，所以**并发边界划得很清楚**：前三并发、第四串行。
   并发前我核对了 `hello_agents` 的源码，确认 `MCPTool.run()` 每次都新建 MCP 会话、
   不在实例上存传输状态，所以多线程是安全的——**这个结论是读出来的，不是试出来的**。
   结果：**82 秒降到 17 秒**。

3. **工程化（40s）**：光跑通不够，我补齐了三块。
   一是**传输层抽象**：把后端地址抽成 `TRANSPORT` 开关，直连 / 云函数 / 微信云托管三条通道
   契约完全一致，**切部署形态只改一个字符串**，页面代码一行不动。
   二是**真的部署上去**：后端打进 Docker 镜像上传微信云托管，小程序用 `callContainer` 调用——
   这条链路走的是微信和腾讯云之间的**私有链路，不受公网开关影响**，所以我可以把公网访问关掉，
   既不用备案域名，又能防别人白嫖我的 LLM 和高德配额。
   三是**安全和测试**：加了 `AUTH_MODE` 三态鉴权和按身份限流，并写了 **75 项零依赖的离线单测**
   ——不联网、不起服务，因为这条链路上最贵的就是 LLM 和高德配额，回归测试不该烧它们。

4. **收尾（30s）**：整个过程我修正了三个「配了就一定把服务搞挂」的环境变量陷阱，
   都写进了部署 runbook。另外按《AI 生成合成内容标识办法》补了显式和隐式双标识，
   连「复制行程」导出的纯文本也带标识，并且写了测试把它钉住。

## 三、高频追问与答法

### A. 架构与 Agent 设计

**Q：为什么要 4 个 Agent？一个 Prompt 加几个工具不行吗？**
> 可以，但会退化成一个「万能客服」，四类任务挤在一段上下文里：景点要关键词检索、天气要单接口、
> 酒店要按位置筛选，编排逻辑还要再合成一次 JSON。拆开的收益是**可并发**（前三互不依赖）
> 和**可降级**（某个 Agent 挂了只丢那一类信息，规划 Agent 仍能出结果）。
> 代价是多花了几次 LLM 调用。这是一个明确的取舍，不是照着教程抄的。

**Q：为什么不并发第 4 个？**
> 它需要前三者的输出当输入，是**真实的有向依赖**，并发不了。并发只在不改变语义的地方做。

**Q：并发安全的依据是什么？靠猜吗？**
> 靠读源码。三条依据：① `MCPTool.run()` 每次 `async with MCPClient(...)` 新建会话，
> 传输层状态不挂在实例上；② 每个 Agent 是独立的 `SimpleAgent` 实例，各自持有 `self._history`；
> ③ 共享的 `HelloAgentsLLM` 初始化后属性只读，底层是 OpenAI SDK（httpx），本身支持并发。

**Q：为什么用 `ThreadPoolExecutor` 而不是 `asyncio`？**
> 因为调用链是**同步阻塞**的（`SimpleAgent.run()` 不是协程）。要用 asyncio 得先包一层
> `run_in_executor`，等于绕回线程池。用线程池直接、可读，且这里瓶颈在**网络 IO**
> （等 LLM 和高德返回），GIL 在 IO 等待时是释放的，所以并发是有效的。
> 真正的收益来源是「把三段等待重叠起来」，不是 CPU 并行。

**Q：MCP 是什么？为什么不直接调高德的 HTTP 接口？**
> MCP 是模型和工具之间的标准协议，好处是**工具发现和调用格式统一**：换一个地图服务商，
> Agent 侧代码不用改。直接用 HTTP 的话，每个工具的入参、返回、错误形态都得自己接一遍。
> 代价是多了一层子进程（`uvx amap-mcp-server`），有冷启动成本——所以我在 Dockerfile 的
> **构建期就把它装好**，让第一笔请求不用现下载。

### B. 高德返回与解析

**Q：高德返回的字段为什么要专门写解析？**
> 因为 `MCPTool.run()` 返回的是**文本**，而且形态不固定：可能是裸 JSON、可能前后带说明文字、
> 可能包在 `{"result": ...}` 里、也可能是 MCP 的 content 数组。所以写了 `_as_payload()`
> **逐层剥壳**。还有两个具体坑：坐标是 `"经度,纬度"` 字符串要拆；距离和时长是**字符串类型**
> （`"1200"`）必须转数字。没有坐标的脏 POI 直接丢弃，因为它在地图上画不出来。

**Q：天气接口有几种返回形态？**
> 两种都要兼容：预报是 `forecasts[].casts[]`（每天一条），实况是 `lives[]`（只有一条，
> 日夜字段共用温度）。只处理一种的话，换一次 `extensions` 参数就解析不出来了。

### C. 前端与跨端

**Q：为什么做两套前端？投入产出比如何？**
> 起因很实际：Web 版的地图依赖高德 JS API，要单独申请 Web 端 Key，还受浏览器跨域约束。
> 小程序内置的 `<map>` 组件**免 Key、无跨域**，而且坐标系默认就是 gcj02——和高德返回的一致，
> 所以**不需要做任何坐标转换**（多做一次转换反而引入误差）。
> 两套前端**共用同一个后端**，后端零改动，成本主要在客户端。

**Q：小程序开发有什么和 Web 不一样的地方？**
> 三个硬约束：① 低基础库版本**不支持可选链和空值合并**，得用 `&&` / `||` 和显式判断；
> ② **WXML 不能调用 JS 函数**，所以格式化、排序、兜底全部要预计算成视图模型；
> ③ **没有 DOM**，`html2canvas` / `jsPDF` 这类库直接用不了，导出必须降级成「复制文本 + 转发」。

**Q：`callContainer` 和 `wx.request` 有什么本质区别？**
> `wx.request` 是普通 HTTPS 请求，**合法域名强制校验**——必须是已备案的域名，
> 而且 `localhost` 在真机上指的是手机自己。
> `callContainer` 是微信云托管的专用通道，走微信和腾讯云之间的**特殊私有链路**，
> **不需要域名、不需要备案，也不受云托管「公网访问」开关的影响**。
> 所以把真机跑通的最短路径是后者。顺带一个坑：`callContainer` **不传 `timeout` 就吃 60 秒默认值**，
> 本链路要 10~25 秒再叠加缩容冷启动会不够，所以显式透传了超时。

**Q：微信云托管和微信云开发是一回事吗？**
> **不是，是两套独立体系。** 云托管的环境在云开发控制台里看不到。所以小程序端维护了
> **两个环境 ID**：`CLOUD_ENV` 给 `wx.cloud.init` 和云数据库用，`CLOUD_CONTAINER_ENV` 给
> `callContainer` 用。混用的症状是 `-601002` 环境不存在。这条是实际踩出来的，已经拆开并加了回归用例。

### D. 部署与运维

**Q：关了公网访问，小程序怎么还能调通？**
> 因为 `callContainer` 根本不走公网。官方原话是**不受公网开关影响**。这是个反直觉但很关键的结论：
> 意味着我可以**只对小程序开放、对公网完全关闭**，天然防别人拿我的后端地址去烧配额。
> 我是关掉公网后**再跑一遍端到端**确认的，不是想当然。

**Q：你说的三个环境变量陷阱具体是什么？**
> ① `GATEWAY_SECRET`：我原本想用它给 `openid` 模式加一道校验，但**云托管网关只注入固定的
> `X-WX-*` 头，没有「注入自定义请求头」的配置项**，配了会导致所有 `callContainer` 请求 401。
> 正确收尾是验证完**关公网**。
> ② `PORT`：我一度在控制台填了 8000，但 Dockerfile 里有 `ENV PORT=80` 兜底，
> 覆盖它反而让健康检查失败——正确做法是**不填**。
> ③ `LLM_BASE_URL`：用 DeepSeek 时**必填**。因为 provider 探测器对 `sk-` + 32 位十六进制的
> Key 会跳过密钥格式分支，落到 base_url 判断；不填就回落 `api.openai.com`，必然 401。
> 这三条都写进了 `backend/DEPLOY-CLOUDRUN.md`。

**Q：镜像里会不会带上密钥？**
> 不会。密钥只在运行时通过环境变量注入，`.env` 被 `.dockerignore` 排除。
> 这点必须较真：**镜像分层是持久的**，密钥一旦被烤进某一层，后续删除也仍能从历史层里翻出来。

### E. 安全

**Q：`AUTH_MODE` 为什么要做成三态？**
> 因为「本地开发别来烦我」和「对外必须收紧」这两个目标是冲突的。
> `off` 给本地（按 IP 限流），`api_key` 给任意公网部署，`openid` 给小程序——
> 小程序天然带 `X-WX-OPENID`，**不用自建登录**。

**Q：那 `openid` 模式安全吗？**
> 有个**真实存在的信任边界**，我没有藏起来：`X-WX-OPENID` 由网关注入，如果服务同时能从公网直连，
> 这个头就是**可以伪造的**。理想解法是再加一层只有网关知道的密钥，但**云托管下做不到**
> （网关无法注入自定义头）。所以正确做法是**验证之后关闭公网访问**——这是个部署约束，
> 不是代码问题，我把它写进了 README 的已知限制和配置自检的告警里。

**Q：限流怎么做的？有什么问题？**
> 按身份分桶的内存计数器，昂贵端点（生成行程）独立收紧到 6 次/分。
> **明确的问题**：计数器在进程内存里，只对单实例精确，多副本下实际放行量是「阈值 × 副本数」，
> 重启就清零。要精确必须换 Redis。这条写在代码的模块注释里，没藏起来。

**Q：为什么用 `secrets.compare_digest`？**
> 普通的 `==` 比较是**短路**的，响应耗时会随匹配的前缀长度变化，
> 理论上可以用来逐位猜密钥。用常数时间比较把这条侧信道堵掉。

### F. 测试与工程规范

**Q：为什么不用 pytest？**
> 刻意选零依赖的独立脚本入口：`python tests/xxx.py` 直接跑，退出码非 0 就是失败。
> 好处是**不引入测试框架依赖、不挑运行环境、看一眼输出就知道哪条挂**，
> 对一个以「能被人 clone 下来就跑」为目标的项目更合适。如果进团队、要接 CI，
> 换成 pytest 只是加个壳。

**Q：为什么强调「离线」测试？**
> 因为这条链路上最贵的两样东西是 **LLM 调用和高德配额**。回归测试如果每次都要真调一遍，
> 要么烧钱、要么因为限额跑不完、要么因为网络抖动而变成假失败。所以断言全部喂样例数据，
> 不联网、不起服务、不读 `.env`。

**Q：前端构建遇到过什么问题？**
> `npm run build` 原本是**直接失败**的，10 个 TypeScript 报错。三类原因：
> ① 缺 `vite-env.d.ts`，导致 `import.meta.env` 和 `*.css` 导入没有类型声明；
> ② `Home.vue` 里用了 `TripFormData & {start_date: Dayjs|null}` 这种交叉类型，
> 结果字段变成 `string & Dayjs`，`null` 谁都不是，赋值直接编译不过——改成 `Omit` 后重新声明；
> ③ `Result.vue` 里两个函数已被内联实现取代但没删，触发 `noUnusedLocals`。
> 顺带把地图 Key 缺失时的静默失败改成了**显式报错**。

## 四、可能被问住的问题（诚实答法）

| 问题 | 不要这样说 | 建议这样说 |
| --- | --- | --- |
| 这个项目是你原创的吗？ | 含糊带过 | **主动交代边界**：「骨架来自 Hello-Agents 教程第 13 章，我做的是工程化改造」，然后给 RESUME.md 里那张对照表。**主动划边界比被追问出来可信得多。** |
| 有真实用户吗？ | 编一个数字 | 「没有，这是我为求职做的项目。所以我更在意**能不能被人 clone 下来就跑**，以及每个优化都有可复现的数字。」 |
| 为什么不做任务队列？ | 说"没必要" | 「**这是已知缺口**。单次请求要同步等 10~25 秒，用户必须停留在页面上。生产化应该改成提交返回任务 ID、再轮询结果。当前没做是因为要把重心先放在链路打通上。」 |
| 你有做过压测吗？ | 硬说有 | 「没有系统压测。我能给的是单次链路的实测耗时，以及限流的**配置级**边界——多副本下不精确这件事我是明确的。」 |
| 为什么不用 Redis / 消息队列 / K8s？ | 堆理由 | 「在这台机器和这个体量上，引入它们的收益低于维护成本。**但如果要多副本，Redis 是第一优先级**，因为限流现在只在单实例内精确。」 |
| Pydantic / 框架细节答不上来 | 编 | 「这个点我需要回去看代码确认，不能凭印象给你一个错的答案。」——**比编错强得多。** |
