## 快速定位：先看这三件事

```
报错了
  │
  ├─ 是在「开发者工具」里报，还是「真机 / 体验版」里报？
  │    真机报「合法域名」→ 见 §四-1（本质是通道没切到 cloud-container）
  │
  ├─ 弹窗里的短句是什么？（我们的错误翻译会给出人话）
  │    弹窗只给人话，**完整原始报错在 Console**，搜 `[request]`
  │
  └─ Console 里搜 `[request][` 这一行，它有通道名 + 原始 errMsg + 翻译结果
```

请求层的日志格式固定为：

```
[request][cloud-container] 调用失败 | errMsg: <原始报错> | 翻译后: <人话>
[request][cloud-function]  调用失败 | errMsg: <原始报错> | 翻译后: <人话>
[request][direct]          调用失败 | errMsg: <原始报错> | 翻译后: <人话>
```

## 一、云托管通道错误（`cloud-container`）

### 现象 → 处置速查

| 现象 / 错误码 | 原因 | 处置 |
| --- | --- | --- |
| `-601002` / 环境不存在 / `env not exists` | `CLOUD_CONTAINER_ENV` 填错，**或填成了云开发环境 ID** | 回**云托管控制台**复制云托管环境 ID（见 02 第 0 节）。两个环境来自不同控制台，不能互换 |
| `-501000` / `Path 访问权限错误` | `X-WX-SERVICE` 服务名不对，或服务未发布成功 | 核对服务名拼写（默认 `trip-api`），确认服务状态为「正常」且有已发布版本 |
| `102002` / `system error`（**第一次**调用失败，重试就通） | 最小副本数为 0，容器冷启动从零拉起 | **正常现象**。见 §一-3；介意就把最小副本数设为 1 |
| 服务名正确，但容器没起来 | 启动阶段配置校验失败（`AMAP_API_KEY` 缺失会被 `validate_config()` 直接抛错） | 看云托管控制台的**部署 / 运行日志**，会打印具体缺哪一项 |
| 容器反复重启、探针始终不健康 | 健康检查路径不是 `/health`，或端口填错 | 路径填 `/health`，端口填 `80`；确认日志里有 `Application startup complete` |
| 所有请求都 401 | 环境变量里**填了 `GATEWAY_SECRET`** | **删掉它**。云托管网关没有注入自定义头的配置项，配了它会让每个请求都缺 `X-Gateway-Secret`（见 §五-2） |
| 容器监听 8000，平台探活 80，永远不健康 | 环境变量里**填了 `PORT`** | **删掉它**。Dockerfile 里已有 `ENV PORT=80` 兜底（见 §五-1） |
| 上传 zip 报体积超限 | > 2 MiB | 确认打包时排除了 `venv/` 与 `__pycache__`（见 02 第 3.2 节） |
| 模拟器正常、真机不正常 | 版本没更新 / 体验版没重新上传 | 重新「上传」并在后台重设体验版 |

### 1. 为什么 `-601002` 十有八九是「填错环境 ID」

微信官方 FAQ 原文：

> **微信云托管和微信云开发是两套独立体系，微信云托管的环境只能在微信云托管控制台看到，
> 在微信开发者工具的云开发控制台中不能看到。**

本项目两者都要用，所以维护**两个**环境 ID：

| 常量 | 属于 | 形如 | 谁在用 |
| --- | --- | --- | --- |
| `CLOUD_ENV` | 微信云开发 | `cloud1-xxxxxxxx` | `wx.cloud.init` / 云数据库 |
| `CLOUD_CONTAINER_ENV` | **微信云托管** | `<你填的名称>-xxxxxxxx` | `callContainer` |

**判别技巧**：看前缀。以 `cloud1-` 开头的基本上是云开发环境，
喂给 `callContainer` 就会报 `-601002`。

> 这个坑已经钉成回归用例：`node tools/test-error-translate.js` 里
> 「callContainer 用哪个环境 ID」一组断言，防止以后又混用。

### 2. `callContainer` 到底受不受「公网访问」开关影响？

**不受。** 这是最容易误解的一点。官方原文：

> 在小程序中使用 callContainer 方法调用服务，使用了微信与腾讯云间的特殊私有链路，
> **不受公网开关影响**。

所以两个访问开关最后都关掉，小程序照样调得通。
**内网访问**是给「同一个环境里的多个服务互调」用的，本项目只有一个服务，用不上。

### 3. 第一次请求失败、重试就通（`102002`）

原因：最小副本数设为 0 时，没有流量就没有实例，第一个请求要等容器从零拉起
（叠加 pip 环境与 MCP 预热的加载）。实测表现是首调返回 `102002`，**重试即成功**。

| 选择 | 代价 |
| --- | --- |
| 最小副本数 = 0 | 没有请求时不产生实例费用，但首调要等冷启动 |
| 最小副本数 = 1 | 没有冷启动，代价是实例常驻产生费用 |

> 演示给别人看时建议设 1 —— 第一下就打开比什么都重要。

### 4. `callContainer` 的超时必须显式传

`callContainer` 的参数与 `wx.request` 一致，**不传 `timeout` 就吃 60 秒默认值**。
本链路实测 17~25 秒，再叠上冷启动，60 秒会不够。

本项目已在 `utils/request.js` 的云托管通道**显式透传** `REQUEST_TIMEOUT = 115000`。
这不是可选项。

## 二、云函数通道错误（`cloud-function`）

| 现象 / 错误码 | 原因 | 处置 |
| --- | --- | --- |
| `-501000` / `-404011` / `FUNCTION_NOT_FOUND` / `could not be found` | 云函数 `proxyTrip` 没上传，或名字不对 | 在开发者工具里右键 `cloudfunctions/proxyTrip` → **上传并部署：云端安装依赖** |
| 弹窗「云函数未配置后端地址」 | 云函数环境变量缺 `BACKEND_URL` | 云开发控制台 → 云函数 → `proxyTrip` → 配置 → 环境变量，新增 `BACKEND_URL` |
| 请求 3 秒就超时 | 云函数**默认超时仅 3 秒** | 调到 **60 秒**（`config.json` 已写 `"timeout": 60`；若工具未采纳，去控制台手动改） |
| 请求 60 秒超时 | 云函数超时上限就是 60 秒 | 这是硬天花板，**比 `wx.request` 的 115 秒更低**。天数多时改用云托管通道更宽裕 |
| `localhost` / `127.0.0.1` 一定失败 | 云函数跑在腾讯云上，那台服务器上没有你的后端 | 后端必须公网可访问（正式部署或内网穿透） |

> 安全说明：云函数只放行 `/api/` 前缀的路径，避免被当成指向任意目标的开放代理（SSRF）。

## 三、云开发 / 云数据库错误

| 现象 / 错误码 | 原因 | 处置 |
| --- | --- | --- |
| `-502005` / `ResourceNotFound` / `Db or Table not exist` | 集合 `trips` 还没建 | 云开发控制台 → 数据库 → 新建集合 `trips`，权限选「仅创建者可读写」 |
| 首页历史条显示灰色「仅本机」 | 云数据库写入失败，已**自动降级** | 这是设计好的降级行为，页面不崩。按上一条建集合即可恢复「已同步云端」 |
| `wx.cloud.init` 报 `-601002` | 该 AppID 下还没开通云环境 | 先在云开发控制台开通环境 |
| 换设备后看不到行程 | `USE_CLOUD_DB` 被设为 `false`，或集合权限不是「仅创建者可读写」 | 检查 `config/index.js` 的 `USE_CLOUD_DB` 与集合权限 |
| 想把云开发环境当云托管用 | 两套独立体系 | 见 §一-1 |

> **注意**：`wx.cloud.database()` 在小程序端**不能建集合**，只能由服务端 SDK 建。
> 所以「新建集合」这一步必须在控制台上做，代码里做不到。

### 云能力和规划请求是两条独立链路

```
接入云开发  ≠  规划请求会上云

规划请求：仍走你在 TRANSPORT 里选的那条通道（默认自建 FastAPI / 云托管）
云开发  ：只用于「存行程结果」这一件事
```

## 四、小程序框架 / 真机相关

### 1. 真机报「请求域名未在合法域名列表中」

这不是配置写错了，而是 `direct` 通道在真机上**根本不可能成立**：

| 约束 | 开发者工具 | 真机 / 体验版 |
| --- | --- | --- |
| request 合法域名 | 可勾选「不校验合法域名」绕过 | **强制校验** |
| `localhost` 指向 | 你的电脑 | **手机自己** |

**处置**：把 `TRANSPORT` 改成 `'cloud-container'` 并填好云托管环境 ID。
完整步骤见 [02-部署到微信云托管-真机跑通](02-部署到微信云托管-真机跑通.md)。

> 注意「不校验合法域名」那个勾选**只对开发者工具有效**，真机跑通才是真验证。

### 2. 真机不复现改动

排查顺序：

1. 换通道后**有没有重新上传**？（改的是小程序代码，必须重传）
2. `CLOUD_CONTAINER_ENV` 是不是填成了云开发那个 ID？
3. 云托管服务的**调用日志**里有没有这次请求？
4. 小程序从「最近使用」里删掉再重进 —— 真机会缓存旧版本。

### 3. 小程序运行时不能用绝对路径 `require`

```js
require('/utils/plan.js')      // ❌ module '/utils/plan.js' is not defined
require('../../utils/plan.js') // ✅ 运行时要求相对路径
```

### 4. 「旅行天数」和日期对不上

后端有 `model_validator` 会**一律按日期区间重算**并覆盖客户端传的值
（不一致时只告警，便于发现客户端 bug 而不影响线上）。
所以以**日期区间**为准，这是唯一真相。

### 5. 小程序没有 DOM

```js
document.querySelector(...)   // ❌ 小程序没有 window / document
html2canvas / jsPDF           // ❌ 依赖 DOM，用不了
```

导出能力的替代方案：复制纯文本 + 转发分享（见 01 第 8 章）。

## 五、后端启动与部署

### 1. 千万别填 `PORT`

云托管的「端口」填 `80`，Dockerfile 里已有 `ENV PORT=80` 兜底。
`.env.example` 里的 `PORT=8000` 是**给本地开发用的** —— 照抄进云托管，容器就会监听 8000，
而平台在探活 80，健康检查永远不会通过，表现为「**构建成功但服务一直起不来**」。

同理 `HOST` 也不用填：启动命令里已经写死 `--host 0.0.0.0`。

### 2. 千万别填 `GATEWAY_SECRET`

这条很反直觉，但**填了会把服务整个搞挂**。

`AccessGuardMiddleware` 的逻辑是：只要 `GATEWAY_SECRET` 非空，就要求每个请求都带
`X-Gateway-Secret` 头并与它比对。而微信云托管的网关**只会注入固定的几个 `X-WX-*` 头，
没有「注入自定义请求头」的配置项** —— 结果是小程序发来的每个 `callContainer` 请求都缺这个头，
**全部 401**。

正确的收尾动作不是配它，而是**验证通过后关掉公网访问**：公网一关，
外部就没有伪造 `X-WX-OPENID` 的入口了。

> 也不要把值硬编码在小程序里自己带 —— 拿到代码就能复制，**它就不再是密钥了**。

### 3. 环境变量报 `InvalidParameter, EnvVarName [XXX ] is invalid`

**方括号里那个空格就是元凶** —— 手填（尤其是从文档表格里复制）极易带进不可见的首尾空格。

**处置**：改用控制台的「JSON」模式粘贴（模板见 `backend/env.cloudrun.example.json`），
从根上避免列错位。若坚持手填，逐格检查首尾有没有空格。

> 值结尾多一个空格同样会让 `LLM_BASE_URL`、`LLM_MODEL_ID` 悄悄失效 —— 症状是 401，
> 但你会以为是 Key 的问题。

### 4. 本地能跑，容器里 401（拿 DeepSeek Key 打到了 OpenAI）

原因：容器里没有 `.env`（被 `.dockerignore` 排除了），而 `LLM_BASE_URL` **必须在控制台显式补上**。

```
没配 LLM_BASE_URL → provider = auto → base_url 为 None
                  → OpenAI SDK 回落到 https://api.openai.com/v1
                  → 拿 DeepSeek 的 Key 打 OpenAI → 必然 401
```

### 5. 上传包体积超限

官方上限 **2 MiB**。本项目实测 `venv/` 有 **280 MB**，整目录传上去必然超限。
去掉 `venv/` / `.env` / `__pycache__/` / `tests/` 之后，整个包**只有 28 KB**。

> 本仓库提供了打包脚本：`python backend/tools/make-upload-package.py`，
> 生成的 `trip-api-upload.zip` 里 `Dockerfile` 位于 zip 根、不含 `venv/` 与 `.env`。

## 六、Console 里那些「不是错误」的信息

开发者工具 Console 里会刷出下面这些，**都不是本项目的 bug**，可放心忽略：

| 信息 | 来源 | 说明 |
| --- | --- | --- |
| `wx.saveFile 即将废弃` / `wx.removeSavedFile 即将废弃` | 开发者工具自动化服务 | 自动化截图时内部「存临时图 → 删临时图」。本项目代码**未调用**这两个 API。判断依据：栈帧只指向 `WAAutoService.js` 这类工具内部包，**不会出现 `app.js`、`pages/**`** |
| `...was preloaded using link preload but not used...` | 开发者工具运行时 | 工具自身的资源预加载提示 |
| `Lazy code loading is enabled...` | 小程序框架 | 对应 `app.json` 的 `lazyCodeLoading: "requiredComponents"`，是刻意开启的 |
| `[自动热重载] 已开启代码文件保存后自动热重载` | 开发者工具 | 保存文件即自动重编译的提示 |
| `[渲染层错误] Listener added for a 'DOMNodeRemoved' mutation event...` | 开发者工具渲染层（Chromium 内核） | `DOMNodeRemoved` 这个 MutationEvent 早已被 Chrome 移除，工具内部仍注册了该类监听。本项目**没有任何 DOM 操作**（小程序也没有 DOM 这个概念） |

**验证方法**：清空 Console，**不做任何自动化截图**、仅连接并读取页面，采集结果为空。

## 七、排错心法：6 条容易让结论失真的做法

这几条都是实际踩过之后总结的，比具体错误码更值钱。

### 1. 断言失败时，先怀疑断言本身

实测两次失败案例都是**测试写错**而非代码有问题：

- 断言「401 响应带 CORS 头」，但请求没带 `Origin` —— CORSMiddleware 只在请求含 `Origin`
  时才追加响应头；
- 断言「首页 AI 标识在首屏内」，但首页并没有 AI 生成的内容，标识是**提交前告知**，
  刻意的位置就是提交按钮正下方。

### 2. 验证弹窗不要用 `mockWxMethod`

它会把被 mock 的 API 变成**空操作**，于是你得出「弹窗没出现」的假结论。
正确做法是**包一层**：保留原调用，只额外记录入参。

验证「复制行程是否带上 AI 标识」用的是同一个套路 —— 包住 `wx.setClipboardData`
抓**真实入参**，比直接调 `buildPlainText()` 更有说服力（后者绕过了页面真实链路）。

### 3. 原生对话框不在 WXML 树里

`page.$$` 查不到它。要眼见为实就**截图**。

### 4. `evaluate` 挂在 `mini` 上，不在 `page` 上

写成 `page.evaluate` 会直接 `TypeError: page.evaluate is not a function`。

### 5. `mini.evaluate` 里传的函数必须自足

它会被序列化后送到页面上下文执行，**捕获不到外部作用域的变量** ——
探针函数里只能引用 `wx` 与全局对象。

### 6. 日志不要直接传 `Error` 对象

```js
console.error('失败', err)            // ❌ 过桥时被序列化成 {}，什么都看不到
console.error('失败: ' + err.message) // ✅ 字符串拼接
```
