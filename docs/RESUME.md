## 一、一句话定位（放项目标题下）

多智能体（4 Agent 并发编排）× 地图 MCP × 小程序云托管全链路落地，从教程示例改造为
**真机可跑、可部署、有测试**的工程化项目。

## 三、项目条目（三个版本，按篇幅挑一个）

### 版本 A · 精简三行（推荐，最常见）

**智能旅行规划助手 · 多智能体 × 地图 MCP × 微信小程序**（独立开发）

- 基于 HelloAgents 搭建 **4 个 Agent 协作**链路：景点 / 天气 / 酒店三路并发检索 + 行程编排，
  把原版的串行调用改为 `ThreadPoolExecutor` 并发，**单次生成从 82s 降到 17s**。
- 统一后端产出**带真实 POI 坐标、天气、路线与预算**的多日行程；抽象三通道传输层
  （直连 / 云函数 / **微信云托管**），**改一个字符串即可切换部署形态**，页面代码零改动。
- 部署到**微信云托管**并让体验版在真机跑通：免备案域名、走微信私有链路、验证后**关闭公网访问**；
  配套 **75 项零依赖离线单测**（鉴权 / 限流 / MCP 返回解析）全绿。

### 版本 B · 单条浓缩（篇幅极紧时用）

**智能旅行规划助手**：用 HelloAgents 编排 4 个 Agent 并发完成景点 / 天气 / 酒店检索与行程编排，
经高德 MCP 获取真实 POI 与坐标；后端 FastAPI 打包上**微信云托管**，小程序端 `callContainer`
走私有链路使体验版真机可用，输出 Web 与小程序两套等价前端。

## 四、可展开的技术点（每条都对应仓库里的真实改动）

| # | 技术点 | 一句话说法（可直接用） |
| --- | --- | --- |
| 1 | **并发编排的边界** | 三个检索 Agent 无依赖故并发，行程编排依赖前序结果故串行；并发安全性是读 `hello_agents` 源码核对 MCP 会话生命周期后得出的，不是试出来的 |
| 2 | **性能优化** | 串行 82.2s（必然撞前端 115s 超时）→ 并发 17.0s；上海 3 天 23.4s，实测录屏上海 1 天 10s |
| 3 | **传输层抽象** | `TRANSPORT` 一个开关切 `wx.request` / `callFunction` / `callContainer`，三通道契约一致、收拢在一处，上层页面无感知 |
| 4 | **微信云托管落地** | 多云托管与云开发是**两套独立环境**（环境 ID 不通用）；`callContainer` 走微信-腾讯私有链路，**不受公网开关影响**，因此可关公网防白嫖 |
| 5 | **排错经验** | 定位并修正三个「配了就把服务搞挂」的环境变量陷阱：`GATEWAY_SECRET`（网关无法注入自定义头 → 全量 401）、`PORT`（覆盖 Dockerfile 兜底 → 健康检查失败）、`LLM_BASE_URL` 漏填（provider 探测器落到 OpenAI 地址 → 401），并写成 runbook |
| 6 | **容错设计** | 云数据库层所有操作**返回 `{ok, reason}` 而从不抛异常**，集合缺失 / 权限不足只降级为「仅本机」，页面不崩 |
| 7 | **接口安全** | `AUTH_MODE` 三态鉴权（`off` / `api_key` / `openid`）+ 按身份分桶限流，昂贵端点独立收紧；密钥比较走 `secrets.compare_digest` 防时序侧信道 |
| 8 | **合规** | 按《AI 生成合成内容标识办法》做**显式 + 隐式双标识**，且**复制导出的纯文本同样带标识**，写进离线自测防回归 |
| 9 | **测试** | 75 项**零依赖离线断言**（不联网、不起服务、不消耗 LLM 与高德配额），覆盖鉴权三态 / 限流 / CORS / 配置自检 / MCP 返回解析 / `travel_days` 收敛 |
| 10 | **工程规范** | 前端 `vue-tsc` 构建全绿；后端 Pydantic v2 迁移后**自身代码零弃用告警**；缺陷以「修根因 + 补回归」的方式收口，而不是绕过 |
| 11 | **跨端取舍** | 小程序无 DOM 故 `html2canvas`/`jsPDF` 不可用 → 导出降级为「复制文本 + 转发」；无 `<canvas>` 支持故用内置 `<map>` 组件，**省掉一个高德 Key、绕开浏览器跨域** |
